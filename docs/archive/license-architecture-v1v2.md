# Aegis 授权体系：结构与使用流程

> 状态：**设计稿，未实现**。基于 2026-10-22 讨论整理。
> 协议细节见 [`desktop/docs/license-protocol.md`](../desktop/docs/license-protocol.md)，
> 本文只讲部署结构、角色分工与操作流程。

---

## 1. 部署拓扑

```
厂商（你）
├─ 厂商密钥对（离线，一次性生成，终身不变）
└─ 厂商签发工具（离线 CLI，唯一持有厂商私钥的地方）
        │
        │ 签 control.cert（每项目一张，5–10 年）
        ▼
客户现场 · 中控主机（每个项目一台，装在中控电脑上）
├─ control.cert            厂商签发的中控授权证书
├─ 委托私钥（加密存储）      多口令槽，任一管理员可解锁
├─ 本地 SQLite             项目 / 设备 / 授权 / 审计
└─ 局域网服务               按需响应子机拉取，不主动推送
        │
        │ 签 license.dat（每设备一张，批量签发）
        ▼
展项子机（N 台 Godot 程序）
├─ control.cert            随程序分发，与中控同一张
├─ license.dat             每设备一张，绑定 device_id
└─ 本地判定，零网络依赖
```

关键点：**厂商私钥永远不进现场**。现场只需要两样东西——`control.cert` 和加密后的委托私钥。

## 2. 三层密钥与操作频率

| 层级 | 谁生成 | 谁持有 | 频率 | 有效期 |
| --- | --- | --- | --- | --- |
| 厂商密钥对 | 你 | 你（离线） | **终身一次** | 永久 |
| `control.cert` | 你 | 各项目中控 | 每项目一次 | 5–10 年 |
| 委托密钥对 | 中控首次启动 | 各项目中控 | 每项目一次 | 与项目同寿 |
| `license.dat` | 客户中控 | 各展项子机 | **每次到期** | 90 天 ~ 1 年 |

> 换厂商密钥 = 所有已交付子机程序验签失败、全部 `control.cert` 作废、必须重新打包发布。
> 这是不可逆操作，密钥对必须一次生成、妥善保管。

### 有效期约束（协议强制）

- `license.dat.expires_at` **不得晚于** `control.cert.expires_at`（`issuance.ts::resolveExpiry`）
- 子机默认有效期 90 天，批量签发时可指定
- 因此 `control.cert` 的有效期决定了客户能续多久，必须在签发时按项目年限给足

## 3. 中控界面结构

三个一级页面，加上两个全局元素。

```
┌─────────────────────────────────────────────────────────┐
│  Aegis 中控      [项目: 成都博物馆 ▾]    证书 2029-12-31 │  ← 全局状态条
│                                          额度 12/50  🔓  │
├─────────────────────────────────────────────────────────┤
│  设备管理  │  签发授权  │  签发记录        [设置]         │
└─────────────────────────────────────────────────────────┘
```

### 全局状态条

| 元素 | 内容 | 说明 |
| --- | --- | --- |
| 项目选择器 | 当前项目名 + 切换 | 只有一个项目时自动选中并隐藏 |
| 证书状态 | 到期日 + 剩余天数 | 剩余 < 180 天转为警示色 |
| 额度 | 已用 / 上限 | 来自 `control.cert.max_devices`，全局额度 |
| 锁状态 | 🔓 已解锁 / 🔒 未解锁 | 点击解锁或手动锁定 |

### 页面 1 · 设备管理

| 列 | 内容 |
| --- | --- |
| 设备 ID | `DEV-xxxxxxxx`（来自 Godot Dock） |
| 状态 | 正常 / 已锁定 / 已解绑 |
| 当前授权 | license_id 尾号 |
| 到期日 | 本地时间 |
| 剩余天数 | **颜色分级：>30 绿，8–30 黄，≤7 红** |
| 最后通信 | 上次成功拉取授权的时间，从未通信显示「—」 |

行内操作：锁定 / 解锁 / 解绑（必填原因）。
顶部操作：登记设备（粘贴设备 ID）、新建项目（内联，填 Dock 显示的 10 位项目 ID）。

> 项目管理并入本页。每个项目基本只建一次，不值得占一级入口。

### 页面 2 · 签发授权

| 区域 | 内容 |
| --- | --- |
| 证书卡片 | license_id、签发方、到期日、项目范围、额度、委托私钥状态 |
| 设备选择 | 多选，**默认按「剩余天数」升序**，默认勾选 ≤30 天的 |
| 到期日 | 日期选择器，默认 = 当前到期 + 1 年（封顶证书到期日） |
| 主按钮 | **「签发」**（唯一按钮，按是否有历史授权自动切换语义） |

首次使用才显示「导入 control.cert」「生成委托密钥」引导；配置完成后收进右上角「设置」。

> `issueLicense` 与 `renewLicense` 在服务层走同一条路径，界面上不需要两个按钮。

### 页面 3 · 签发记录

审计列表：时间、操作人（口令槽）、动作、对象、结果、错误码。
筛选：动作类型 / 设备 ID / 时间范围。支持按设备钻取历史。

### 设置（抽屉）

| 分组 | 内容 |
| --- | --- |
| 中控证书 | 查看、替换（替换后旧授权仍有效，但新签发用新证书） |
| 委托密钥 | 导出公钥参数、添加/删除管理员口令槽、修改自己的口令 |
| 局域网 | 监听端口、开关、当前在线设备数 |
| 数据 | 打开数据目录、备份数据库 |

## 4. 使用流程

### 阶段 0 · 一次性初始化（你，只做一次）

1. 生成厂商 RSA-2048 密钥对，私钥存离线介质
2. 导出公钥 `{kty, n, e}`，写入两处信任根：
   - `desktop/src/main/vendor-trust.ts` → `EMBEDDED_VENDOR_PUBLIC_KEY`
   - `godot/addons/aegis/aegis_vendor_key.gd` → `VENDOR_PUBLIC_KEY.n`
3. `npm run build` 构建中控；`python godot/package_addons.py` 重新打包插件
4. 妥善备份厂商私钥（丢失 = 无法再签任何 `control.cert`）

### 阶段 1 · 新项目交付（你 + 客户，每项目一次）

1. 客户现场安装中控，首次启动进入引导页
2. 引导页自动生成委托密钥对，显示**委托公钥参数**（可复制 / 二维码）
3. 客户把公钥发给你
4. 你用厂商签发工具生成 `control.cert`：
   - `license_id`：如 `VND-CDMS-2026-001`
   - `project_ids`：Dock 显示的 10 位项目 ID
   - `max_devices`：合同约定台数
   - `expires_at`：项目年限（建议 5–10 年）
5. 回传 `control.cert`，客户在引导页导入
6. 客户设置第一个管理员口令（创建第一个口令槽）
7. 把同一张 `control.cert` 随子机程序分发（放工程根目录 / exe 同目录）

### 阶段 2 · 日常运营（客户中控，高频）

1. 每台子机启动，Dock 显示项目 ID / 设备 ID
2. 在中控「设备管理」登记设备（粘贴设备 ID）
3. 「签发授权」多选设备 → 设到期日 → 点「签发」
4. 授权通过局域网下发（子机临期时自己来拉），或导出 zip 人工拷贝
5. 子机验签通过，正常运行

**续期不需要人工介入**：子机在到期前 30 天自动来拉，中控返回最新授权即可。

### 阶段 3 · 异常处理（低频）

| 场景 | 操作 |
| --- | --- |
| 加一个管理员 | 设置 → 委托密钥 → 添加成员 → 生成一次性注册码 → 对方输入并设自己的口令 |
| 某管理员离职 | 删除他的口令槽，其他人不受影响 |
| 中控电脑坏了 | 新机器装中控 → 导入 `control.cert` + 恢复加密私钥文件 + 恢复数据库 → 任一管理员口令解锁 |
| 全部口令丢失 | 无法自行恢复，必须由厂商重签 `control.cert`（委托公钥需更换） |
| 证书快到期 | 厂商签一张新 `control.cert`（可延长有效期 / 调整额度），客户导入替换 |

## 5. 子机侧行为（无心跳）

**核心原则：网络只能延长授权，永远不能维持授权。**

子机的有效性只由三样东西决定：磁盘上的 `license.dat`、`control.cert`、本地时钟。
网络状态**不参与**判定。

| 阶段 | 行为 |
| --- | --- |
| 有效期内 | 正常校验，**不访问网络**；中控宕机不影响任何设备 |
| 距到期 < 30 天 | 后台异步尝试拉取新授权：超时 2 秒、失败静默、不改本地状态 |
| 已过期 | **暂停业务而非退出进程**，显示「授权已到期」界面，每 5 分钟重试 |
| 拿到新授权 | 验签 → 原子替换 `license.dat` → 自动恢复，无需重启 |

### 为什么不做心跳

1. 心跳把「授权有效性」绑定到「外部服务可用性」，中控一台机器决定整个展馆
2. 批量签发的授权往往同日到期，宽限期又是同一常量 → 中控坏 N 天，第 N 天所有展项同一秒黑屏
3. 几十台子机同时重连，中控刚恢复就可能被压垮

### 防同日全灭：错峰到期

批量签发时按 `hash(device_id)` 给到期日加 ±14 天偏移。20 台设备分布在两周内，
中控坏 3 天不会全灭。

## 6. 局域网续期协议

### 发现（UDP，仅按需触发）

```
子机 → 255.255.255.255:47820   AEGIS-DISCOVER/1 <device_id> <project_id>
中控 → 单播回包                  AEGIS-HERE/1 <host> <port> <control_license_id>
```

子机缓存 `host:port` 下次直连；连不上再广播。**不做常驻广播**，避免广播风暴。

### 拉取（TCP，明文 JSON）

```json
请求 { "v":1, "device_id":"...", "project_id":"...",
       "current_license_id":"...", "last_expires_at":"...", "nonce":"..." }

响应 { "v":1, "status":"issued"|"unchanged"|"revoked"|"denied",
       "license":"<信封文本>", "reason":"..." }
```

中控侧收到请求后重新执行全部校验：设备已登记且未解绑、项目在证书范围、额度未超、设备未锁定。
锁定设备返回 `denied` —— 顺带获得「远程锁定」能力。

### 为什么明文够用

- 响应由委托私钥签名，中间人改不了内容，只能拒绝服务
- 重放被「只接受 `expires_at` 严格更晚的授权」这条单调性挡住
- 伪造请求骗取授权没有价值：`license.dat` 绑定 `device_id`，别的设备拿去验不过（`0x035`）

## 7. 安全边界

### 委托私钥的存储

**当前实现有漏洞**：`delegated-key.ts` 明文写 `userData/keys/delegated.key.pem`，
`chmod 0600` 在 Windows 上基本无效。任何能登录该账户的人都能拷走私钥。

目标方案：**一个私钥，多个口令槽**

```
委托私钥（AES-256-GCM 加密落盘）
    ↑ 由 DEK 加密
DEK
    ↑ 被各自的 KEK 包裹
├─ 槽 1：scrypt(你的口令) → KEK
├─ 槽 2：scrypt(同事 A 的口令) → KEK
└─ 槽 3：scrypt(同事 B 的口令) → KEK
```

- 任一口令解出同一个 DEK，互相不知道对方口令
- 某人离职删掉对应槽即可
- 审计记录「哪个槽解锁」，比现在取 OS 用户名（可伪造）可信

### 分级解锁

| 操作 | 是否需要口令 |
| --- | --- |
| 查看设备、到期日、审计记录 | 否 |
| 签发、续期、导入私钥、增删管理员 | 是（解锁后缓存 8 小时） |

### 必须如实告知的限制

- **口令只提高门槛，不防逆向**。签发逻辑在本地，理论上可 patch 掉校验
- 真正的强控制要求私钥不在现场（在线签发 / 硬件令牌），但与「现场一键签发」冲突
- 委托私钥保存在客户中控上，普通 Windows 环境无法保证不可提取；本方案只提高攻击成本

## 8. 场景：15 天试用

### 关键判断：试用版**不能**给中控

如果试用客户拿到中控 + 委托私钥，他可以自己无限续期，试用就失去意义。
所以试用必须是**离线预签**，客户手上只有两个文件，没有任何签发能力。

### 试用包构成

| 文件 | 内容 |
| --- | --- |
| `control.cert` | 厂商签的**试用专用证书**：`project_ids` = 试用工程 ID，`max_devices` 放宽，有效期 1 年 |
| `license.dat` | 为该客户 `device_id` 单独签的 15 天授权，`features` 含 `trial` 标记 |
| 程序 exe | 内置同一把厂商公钥 |

所有试用客户共用同一张试用 `control.cert`（因为是同一个 Godot 工程，`project_id` 相同），
但每人的 `license.dat` 不同（绑定各自的 `device_id`）。

### 首次激活流程

1. 客户运行 exe → 无授权 → 显示**申请码**（含 `device_id` + `project_id`）+ 联系方式
2. 客户把申请码发给你
3. 你用内部中控（或厂商 CLI）签一张 15 天的 `license.dat`
4. 客户在到期界面的「导入授权」里粘贴或选择文件 → 立即生效

> 当前实现缺失：无授权时直接 `quit(1)`，客户看不到 `device_id`，无法完成上述第 1 步。
> 必须改成「显示申请码 + 导入授权入口」。

### 15 天到期后

| 情况 | 操作 |
| --- | --- |
| 客户决定购买 | 签一张正式授权（1 年）覆盖旧的 `license.dat` → 程序自动恢复，**不需要重装** |
| 客户还在评估 | 可再签一张短期授权（建议只给一次，避免事实上的永久免费） |
| 客户不买 | 不做任何事，程序停在「试用已结束」界面 |

到期界面必须提供**「导入授权文件」**入口。否则客户拿到新授权也只能重装程序，体验极差。

### 试用与正式在协议层的区别

**没有区别。** 都是 `machine-license` 信封，只是 `expires_at` 不同。
`trial` 只是 `features` 里的一个标记，用于让子机显示不同文案，不参与任何校验决策。

> 当前缺陷：`issuance.ts:173` 硬编码 `features: []`，证书与签发参数里的 `features`
> 从未传到子机。要让 `trial` 标记生效，必须先修这条传递链路。

## 9. 场景：小项目同机部署

适用于场地小、没有独立中控主机的情况：

```
机器 A（兼职中控）           机器 B              机器 C
├─ Aegis 中控                └─ 子机 B           └─ 子机 C
└─ 子机 A
```

一台机器同时跑 Electron 中控和 Godot 子机 A，B、C 是独立机器。

### 三个必须处理的问题

**① 授权文件路径不通**

中控把授权写在 `userData/licenses/*.json`，子机读的是 exe 同目录的 `license.dat`，
两者不是同一个位置。

解决（按优先级）：
1. 子机拉取时**优先尝试 `127.0.0.1`**，同机秒连，不依赖广播是否回环
2. 中控设置里可配置「同机子机目录」，签发后自动原子写入一份 `license.dat`
3. 兜底：手工导出

**② 同机多程序的 `device_id` 会冲突**

`aegis_device.gd:31-36` 的 `device_id` 只由 `OS.get_unique_id()` 派生，**没有项目盐**。
同一台机器上跑两个不同的 Godot 工程，会得到**完全相同**的 `device_id`，
而 `devices_active_unique` 索引禁止一个 `device_id` 同时属于两个项目 —— 第二条登记直接被拒。

解决：`device_id = "DEV-" + sha256(unique_id + project_code)[0:16]`。
加了项目盐后，同一台机器在不同工程里有不同身份，互不干扰。

> 代价：`device_id` 变化会让**已签发的授权全部失效**。现在没有生产授权，改的成本最低；
> 一旦交付了第一批客户，再改就要全量重新登记 + 重签。

**③ 安全降级：委托私钥和子机在同一台机器**

这台机器既持有签发能力，又运行被授权的程序。子机 A 若能读到加密私钥文件并破解口令，
就能给自己签任意期限的授权。

缓解措施（缺一不可）：
- 委托私钥必须加密存储（见 §7），不能是明文 PEM
- 中控**空闲 15 分钟自动锁定**，不长期驻留解锁状态
- 子机 A 与中控使用不同的 Windows 账户运行（可选，进一步隔离）

### 容量提醒

中控是 Electron 应用，常驻内存约 150–250 MB。和展项程序同机时要注意总内存预算，
建议中控「用完即关」或空闲自动锁定后允许关闭，不要当成常驻服务。

| `godot/addons/aegis/aegis_license.gd` | 新增 `RENEW_WINDOW` 常量与临期判定 |
| `src/renderer/src/views/*` | 四页合并为三页 |

### 建议实施顺序

1. **`device_id` 加盐**（改一行，越早越好——一旦有客户交付就改不动了）
2. **错峰签发 + `features` 传递**（纯服务层，风险低，可独立测试）
3. **加密私钥 + 口令槽**（安全收益最大，不碰协议）
4. **厂商签发 CLI**（解锁 `control.cert` 与试用 `license.dat` 产出能力）
5. **到期暂停而非退出 + 申请码界面**（Godot 侧，需重跑失败拦截测试）
6. **局域网拉取（含 `127.0.0.1` 优先）**（新增模块，工作量最大）

## 11. 与初版设计的差异

| 项 | 初版 | 现方案 | 原因 |
| --- | --- | --- | --- |
| 子机通信 | 每 10 分钟心跳 | 无心跳，仅临期拉取 | 避免中控单点导致全馆级联失效 |
| 到期处理 | 直接 `quit(1)` | 暂停业务，保留进程 | 退出后无法再要授权，且展馆黑屏 |
| 宽限期 | 固定 7 天 | 取消宽限，改 30 天提前量 + 错峰 | 宽限期只是把级联推迟，不消除 |
| 到期日 | 批量同一天 | 按设备错峰 ±14 天 | 避免同日全灭 |
| 委托私钥 | 明文 PEM | AES-GCM + 多口令槽 | Windows 上 0600 无效，等于公开 |
| 界面 | 四页 | 三页 | 项目管理低频，并入设备管理 |
| 签发按钮 | 签发 / 续期两个 | 一个 | 服务层走同一路径，无差别 |
| `device_id` | 仅 `OS.get_unique_id()` | 加 `project_code` 盐 | 同机多程序会拿到同一个 ID，被唯一索引拒绝 |
| 无授权状态 | 直接退出 | 显示申请码 + 导入授权入口 | 试用激活与到期换证都需要，退出后无法自救 |
| 试用 | 未定义 | 离线预签，客户无中控 | 客户持有委托私钥就能无限自续，试用失去意义 |
